# LinkCOM Windows 版测试指南

本文说明如何在 Windows 上构建、运行并测试 LinkCOM 的 Flutter 桌面端（共享端/链接端/设置 同一程序，左侧三导航；`IndexedStack` 保活，切导航不丢串口/中继连接；宽屏用可折叠侧栏（点侧栏头部切换），窄屏/竖屏改为左上角菜单键打开的抽屉）。

> 与 Android 不同，Windows 端**链接端不接本地串口**——它只通过中继服务器接收/发送。要验证"链接端收到串口数据"，必须由共享端（硬件串口、或另一台设备/浏览器共享端）经同一服务器转发。

---

## 1. 构建与运行

### 开发模式（推荐先这样测，可热重载 + 看控制台日志）
```powershell
cd linkcom_flutter
flutter run -d windows
```
- 首次会自动 `flutter pub get`（需国内镜像，已配置 `PUB_HOSTED_URL`/`FLUTTER_STORAGE_BASE_URL`）。
- 控制台会打印 `连接中继: ws://...` 等诊断日志。

### 发布模式（产物可直接分发）
```powershell
flutter build windows
```
产物：`linkcom_flutter\build\windows\x64\runner\Release\LinkCOM.exe`
双击即可运行，无需安装。

### 环境要求
- Windows 10 / 11（兼容到 Win7 的 PySide6 旧版已弃用，Flutter 版最低 Win10）。
- 已装 **Visual Studio 2022 + "使用 C++ 的桌面开发"** 工作负载（Flutter Windows 构建必需）。
- 串口层用 `serial_port_win32`（纯 Dart FFI，**免插件注册、免额外驱动**，自动枚举 `COMx`，覆盖 CH340/CP210x/FTDI/PL2303/CDC 及蓝牙虚拟 COM）。

---

## 2. 启动中继服务器（联调前提）

本机双端/与 Web 互通都需要一个运行中的 `server.js`：
```powershell
cd LinkCOM            # 仓库根目录
node server.js
```
启动后：
```
LinkCOM 服务器已启动: http://localhost:8080
  共享端: http://localhost:8080/        (选择 COM 口并共享)
  链接端: http://localhost:8080/?mode=link
```
默认端口 8080（`PORT` 环境变量可改）。应用「设置」Tab 里填的中继地址需与之相同（默认 `ws://localhost:8080/ws`）。

---

## 3. 没有真实串口怎么测（虚拟串口 / 自环）

### 方案 A：虚拟串口对（最省事，推荐）
用 **com0com**（免费，Windows 虚拟 null-modem）创建一对互联 COM，例如 `COM3 ↔ COM4`：
- 共享端开 `COM3`；用「串口调试助手 / PuTTY / SSCOM / Python pyserial」打开 `COM4` 互发。
- 这样可验证：Win32 串口读写、时间窗口聚合（不卡）、GBK/UTF-8 解码、日志着色。
- 若只想看"共享端自发自收"，把 USB-TTL 适配器的 **TX、RX 短接** 接到同一 COM 即可。

### 方案 B：双 USB 串口适配器
两个适配器都插上（如 `COM5`/`COM6`，彼此 TX-RX 交叉连接），一个当共享端，另一个用串口助手对发。

> 注意：Windows 端链接端**没有本地串口**，所以"链接端收串口数据"必须靠下面的联调场景（方案 C/D）经服务器转发。

---

## 4. 测试场景清单

### 场景 A：共享端本地回环（仅验证串口层）
1. 准备虚拟串口对或 TX-RX 自环。
2. 「共享端」Tab → 展开「串口配置」→ 选 COM、设波特率/编码 → 打开串口。
3. 在发送框输入文字点「发送」，用串口助手在另一口回发。
4. 验证点：
   - UI **不卡死**（连续数据靠聚合，已修复 `dataPollingInterval`）。
   - 中文**不乱码**（GBK 选 GBK、UTF-8 选 UTF-8）。
   - 日志按 发送/接收/错误/系统 着色；字节统计正确。

### 场景 B：本机双端联调（Flutter 共享端 ↔ Flutter 链接端）
1. `node server.js` 已在跑。
2. 左侧「共享端」：填房间码（如 `test`）→ 开始共享 → 打开 COM。
3. 左侧「链接端」：填**同一房间码** → 连接房间。
4. 验证点：
   - 链接端状态行 `WS:已连  串口:已开`（共享端先开 COM 或后开都应同步成"已开"）。
   - 共享端发 → 链接端收；链接端发（需共享端串口已开）→ 共享端/串口助手收。
   - 断开共享端 COM，链接端 `串口:未开` 自动复位；重新打开后恢复。

### 场景 C：Flutter 共享端 ↔ Web 链接端（浏览器）
1. 浏览器打开 `http://localhost:8080/?mode=link`，房间码填与 Flutter 共享端相同。
2. 验证点同 B；重点验证**跨端编码同步**：Flutter 共享端改编码（GBK↔UTF-8），Web 链接端即时跟着变；Web 改聚合参数回车，Flutter 共享端收到并重开串口。

### 场景 D：Flutter 链接端 ↔ Web/手机 共享端
1. 浏览器/手机打开 `http://<服务器IP>:8080/`（共享端），选 COM、开串口、填房间码。
2. Flutter「链接端」Tab 填同房间码连接。
3. 验证点：Web 共享端串口数据 → Flutter 链接端显示；Flutter 链接端发送 → Web 共享端写串口。

### 场景 E：配置双向同步
- 链接端展开「串口参数」改波特率/停止位/编码/聚合窗口 → 应用 → 共享端收到并重开串口（日志出现"应用链接端参数"）。
- 共享端改参数 → 链接端下拉实时刷新（编辑器用 `value:` 而非 `initialValue`）。

### 场景 F：快速发送 / 快速匹配（嗅探）
- 「快速发送」增条目（文本/HEX/CRLF/延迟/轮询），验证单发/顺序/轮询；配置持久化（重开 App 仍在）。
- 「快速匹配」加规则（keyword/方向/去重/高亮），收发时命中行高亮。

### 场景 G：主题与折叠面板
- 左侧「设置」切 自动/白天/黑夜，重启后保留。
- 共享端与链接端均是**单个「房间配置」折叠面板**（与 Web 端一致，串口配置+房间/中继配置合并一处）：共享端顺序为 串口选择→打开/刷新→串口参数→房间码/密码/服务器→开始共享；链接端顺序为 房间码/密码/服务器→连接房间→共享端串口参数。连接后自动收起，收起后摘要显示房间码/端口/波特率/连接态。点标题可展开。
- 左侧导航在宽屏默认展开、竖屏默认折叠；点头部菜单图标可切换。

### 场景 H：断线自愈
- 杀掉 `node server.js` → 链接端 `WS:未连`；重启服务器 → 约数秒内自动重连并重新加入房间、状态自愈。
- 改「设置」里服务器地址（防抖 700ms 后自动换连）。

## 5. 已知坑 / 必验项
- **连 COM 后 UI 卡死**：已通过调大 `dataPollingInterval`(10ms)+时间窗口聚合修复；若仍卡需排查读循环。
- **GBK 中文乱码**：发送端与接收端编码必须一致（串口层用 `gbk_codec`）。
- **Windows AXTree 报错** `Failed to update ui::AXTree ...`：已通过根布局用 `SingleChildScrollView`（非 `ListView`）+ 可折叠面板不含 `ListView` 规避；鼠标悬停切换不应再报。
- **链接端"串口未开"不同步**：已修复（`serial-config`/`serial-state-query`/`closed` 全链路）；连上房间应即时见"已开"。
- 共享端「打开/关闭串口」「刷新」按钮**刻意放在折叠面板外**，折叠后仍可断开。

---

## 6. 调试技巧
- 开发模式 `flutter run` 控制台看 `print` 诊断（枚举失败、连接地址、应用参数等）。
- 应用内每个 Tab 下方都是统一的「终端」(TerminalView): 第一行 文本/HEX/时间戳/编码/聚合(ms)/缓冲(KB) + 自动滚动/暂停; 第二行 接收/发送字节 + 清空/导出历史(保存为文件); 第三行 显示区(内容少时自适应高度, 超上限滚动); 下方发送区(多行 2~10 行, 右侧 发送/HEX/加\r\n, 竖屏换到第二行)。导出历史用 file_saver 保存 .txt。
- 想抓 Flutter 框架层异常：`flutter run` 终端会直接输出红屏堆栈。
